## 1. Галлюцинации LLM

**Причина.** Модель склонна «достраивать» связь по совпадению слов. Пример: требование «отменить заказ» и тест `should cancel subscription` — оба про cancel, но про разное.

**Контроль.** Evidence gate (`demo/src/validate.py`):

1. `file` обязан матчить `^tests/(.*/)?test_[^/]+\.py$`;
2. `file` обязан совпадать с файлом из `test_id`;
3. диапазон строк обязан лежать внутри функции теста из `tests.jsonl`;
4. `quote` после нормализации пробелов обязан быть **дословной подстрокой** указанных строк.

При провале любого пункта доказательство отбрасывается. Если у AC не осталось доказательств, статус понижается до `absent`, `confidence ≤ 0.3`, в `gaps` пишется `evidence_unverified`.

**Измерено.** В финальном прогоне 22 цитаты прошли проверку, 1 неточная цитата DeepSeek V4 Pro (R4.AC4 — в цитате пропущена строка `last_frame = exc_info.traceback[-1]`) отклонена, и AC честно понижен до `absent`. Стресс-тест на бесплатной Nemotron: 8 неточных цитат отклонены, ни одна не дошла до отчёта. Отдельный тест `demo/tests/test_evidence_gate.py::test_gate_rejects_invented_quote` подтверждает, что подменённая цитата (`500` вместо `422`) отклоняется. Тест `test_gate_rejects_production_file` подтверждает, что `app/main.py` не может быть источником доказательства.

**Остаточный риск.** Gate проверяет *подлинность* цитаты, а не её *достаточность*. Формально верная строка может не покрывать весь AC. Поэтому score считается по AC, а не по факту наличия цитаты.

## 2. Хрупкость лексического режима (offline-валидатор = baseline)

**Причина.** В offline-режиме решение принимается по взвешенному совпадению ключевых слов, а лексика теста и требования может не совпадать. В финальном прогоне решение принимает LLM (`deepseek-v4-pro`); offline сохранён как детерминированный baseline и режим для CI без LLM-ключа.

**Контроль.**
- три ранкера (BM25, эмбеддинги, keyword-overlap) объединяются через RRF;
- общие термины (`status_code == 200`, `response.json()`) весят 0.5, профильные — 1.0;
- для статуса `covered` требуется хотя бы один профильный термин;
- порядок ключевых слов задаёт приоритет выбора строки-доказательства;
- доменный фильтр: офлайн-валидатор доверяет только файлам, отобранным для этого требования (контрольные файлы остаются в пуле, чтобы ложные срабатывания были измеримы);
- `excludes` запрещает закрывать позитивный AC негативным тестом (например, `422` не может доказать «валидное тело → 200»).

**Измерено.** P@5 = 0.92 на 35 размеченных парах; в финальном LLM-прогоне agreement со статусами baseline 18/20 (расхождения: R2.AC4 и R4.AC4).

**Известные отказы (важнее успеха).** Два межмодельных расхождения вынесены в отчёт, а не спрятаны:

- **R2.AC4** («yield-зависимость выполняет teardown») — `partial` в offline-baseline (и у `glm-5.3`): прямой тест teardown (`tests/test_dependency_contextmanager.py`, `state["/sync"] == "generator completed"`) не входит в пул R2 — это retrieval-пробел (составляющая Recall@pool 0.96). `deepseek-v4-pro` оценил этот AC как `covered`, сочтя косвенное доказательство («Exception after yield») достаточным.
- **R4.AC4** (traceback до строки raise) — `covered` в offline-baseline, `absent` у `deepseek-v4-pro`: тест найден верно, но цитата приведена недословно (пропущена строка `last_frame = ...`), и evidence gate отклонил её.

Оба случая оставлены как есть и вынесены в `gaps`: первый — суждение о достаточности доказательства, второй — сработавший контроль подлинности цитаты.

## 3. Недетерминированность

**Контроль.**
- offline-режим детерминирован: нет сэмплирования, все сортировки с явным tie-break по `test_id`;
- эмбеддинги кэшируются по хэшу `backend + corpus` в `.cache/emb`;
- для LLM-режима: `temperature=0`, попытка передать `seed`, строгая схема ответа, до 3 retry;
- `run_meta.json` фиксирует commit, модель, backend, seed и тайминги.

**Измерено.** Три повторных retrieval-прогона дали Jaccard = 1.0 по пулам всех требований.

**Ограничение.** Для LLM-режима детерминизм не гарантируется провайдером. `run_meta` пишет фактическое состояние, а не обещание.

## 4. Пропуск релевантного теста

**Причина.** Пул ограничен 25 тестами на требование; при 649 тестах это сознательное сжатие.

**Контроль.** Три ранкера, глубина 30 на каждый, RRF, cap 25. `retrieval_debug.json` хранит для каждого AC позиции кандидата в каждом ранкере — пропуск можно объяснить, а не только констатировать.

**Измерено.** Recall@pool = 0.96. Единственный пропуск: `tests/test_request_params/test_body/test_required_str.py::test_required_str_missing` для R1 — релевантный тест не попал в пул из 25. Это зафиксировано, а не скрыто.

## 5. Фиктивное покрытие

**Причина.** Тест может существовать, но не содержать проверок.

**Контроль.** AST-парсер извлекает `ast.Assert` и блоки `pytest.raises` с точными строками. Тест без проверок не может стать источником `covered`. Счётчик `tests_without_asserts` выводится в метаданные.

**Измерено.** 649 тестов, `tests_without_asserts = 0`. Тестов, где единственная проверка — `pytest.raises`, отдельно посчитано в `tests_with_raises_only`.

**Ограничение.** Наличие assert не равно его осмысленности. Это контролируется только вручную и частично — mutation-критерием в gold set.

## Чего в контроле нет

1. **Исполнение тестов.** Система не знает, проходит ли тест и покрывает ли он строки.
2. **Полнота AC.** Если требуемое поведение не описано в AC, оно не будет найдено — и это не будет видно как gap.
3. **Семантика вне лексики.** Offline-режим не понимает синонимы, которых нет в `text_en`/`keywords`.
4. **LLM-режим обкатан на каскаде из четырёх режимов, но короткими сериями.** DeepSeek V4 Pro прошёл один финальный прогон (5 вызовов, 0 retry); длинные серии и повторные прогоны DeepSeek не испытывались. Бесплатная Nemotron в стресс-тесте показала ожидаемую нестабильность (70% self-agreement) — аргумент за сильную модель и повторные прогоны в CI.
